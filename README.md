# 表格数据问答 · 最小链路

把「一句话查数」拆开看：问句 → 字段匹配 → SQL 生成 → 执行 → 归因。

这个仓库不是一个大模型应用，而是**一条链路的可运行拆解**。目标是把「模型为什么选错了字段」这件事变得可观察、可归因。

---

## 它想解决什么

电商数仓里，回答一句「上个月益生元品类的支付金额是多少」，实际要走这几步：

1. 想清楚「支付金额」对应哪个字段——`pay_amount` / `total_amount` / `settle_amount` 的中文名都像"金额"
2. 确认品类取值——字典里写"益生元"，库里存的可能是"益生元益生菌固体饮料"
3. 对齐时间口径——`pay_time` 是支付时间，`create_time` 是下单时间
4. 写 SQL、跑、对账

真正耗时的不是第 4 步，是前 3 步。而这三步恰好都可以被自动化——只要字段字典足够干净。

## 一个反直觉的结论

> 这类系统失败，绝大多数不是因为模型不够聪明，而是因为**元数据层不干净**。

演示里的案例 B 就是为了说明这件事：SQL 语法正确、字段选对、时间范围没错，校验器全部通过，**返回 0 行**。根因是 `category_name` 的实际取值里没有"少女丹"，存的是"少女丹·私护凝胶"。

这类问题调 prompt 是修不好的，只能去补取值映射。

---

## 链路设计

| 环节 | 做什么 | 典型失败模式 |
|---|---|---|
| 意图解析 | 自然语言 → 结构化槽位（指标/维度/时间/粒度） | 槽位拆错，"上个月"被解析成滚动 30 天 |
| 字段匹配 | 按字典注释检索候选字段，打分排序 | 注释重复导致选错；注释缺失导致选不到 |
| SQL 生成 | 拼表连接、过滤、聚合 | 漏了 `order_status` 过滤；时间边界用 `BETWEEN` 漏掉当天末尾 |
| 执行 | 连接数据库取数 | 空结果被当成"值为 0" |
| 归因 | 判断错在哪一层 | 把元数据问题误判成模型问题 |

最后一行是重点。**归因能力决定这个系统能不能迭代**——没有归因，就只能盲目换模型、改 prompt。

## 评测

演示里放了 6 条用例，通过 3 条。三条失败分别是：

| 失败类型 | 表现 | 根因层 |
|---|---|---|
| 元数据 | 返回 0 行 | 字典取值与真实数据不一致 |
| 口径 | 退款率算出 12.7%，期望 8.2% | 分母定义分歧 |
| 编排 | 查询超时中断 | 触发步数上限 |

**没有一条是模型能力问题。**

这套评测集的设计原则：每条用例都要能明确归因到某一层。如果一条失败说不清是自己的问题还是数据的问题，它就没有价值。

---

## 哪里还需要人

这套东西的目标不是全自动，而是把人的介入点变清晰：

- **枚举值确认**：模型不知道"益生元"在库里的完整写法，需要一次人工补充映射
- **口径判定**：同一指标不同入口数值不一致时，机器判断不了哪个对，这是业务定义问题
- **高风险动作**：只读查询可以放开，写入/删除必须人工确认

## 文件

| 文件 | 说明 |
|---|---|
| `export_dict.py` | 从 MySQL `information_schema` / Excel / CSV 导出字段字典为 JSON，并做质量检查 |
| `demo/table-rag-demo.html` | 链路演示页，单文件，浏览器直接打开 |
| `cases/weekly-report-automation.md` | 实战案例：广告日报自动化的口径决策与验证方法 |

### export_dict.py

```bash
python export_dict.py
```

改脚本顶部配置区的三行即可。输出：

- `dict.json` — 每个字段带类型归类、是否可聚合、是否枚举字段、检索文本
- `dict_quality.md` — 注释质量报告，按五类问题分类

五类检查：无注释 / 占位符 / 注释过短 / **同表内重复** / 枚举无取值说明。

其中「同表内重复」是最隐蔽的一类——两个字段注释都写成"金额"，看起来一切正常，但检索时必然选错。这是唯一一类**静默失效**的问题。

## 已知局限

- 演示页里模型调用和数据库查询是写死的 mock，没有真实接入
- 字段名与取值用的是示意结构，真实项目需按自己的字典调整
- 只覆盖单表/简单 join 场景，多表复杂关联尚未验证
- 没有做中文分词的优化，纯靠注释文本相似度

---

## 数据安全

**本仓库不包含任何真实业务数据。** 字段字典、表结构、查询结果均未提交（见 `.gitignore`）。

如果要在自己环境跑：

```gitignore
dict.json          # 含真实字段名
dict_quality.md    # 含真实字段名
*.xlsx             # 原始字典
```

数据库连接一律使用只读账号。
